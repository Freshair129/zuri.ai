FLOW 04 · DATA FLOW

LINE webhook จนถึงคำตอบและหลักฐาน

Core ตรวจ webhook และบัญชี LINE จากนั้นรับงานแบบ durable ให้ executor ที่ Core เลือกทำงาน ก่อนตรวจ fence แล้วส่งผ่าน Integration

อ่านเพิ่มเติม: LINE OA Studio owns account/job state; Integration owns provider secrets and transport; CRM owns conversation/message records; Agent owns answer contract. Conversation Runtime has no direct Prisma/table access and a ready process does not select its executor cohort.

FLOW 06 · DATA FLOW

GenesisRAG17: รับแหล่งข้อมูลจน publish

Zuri ทำ admission และ Tier 1 stages, MSP relay, GKS ตัดสินความรู้ canonical, GenesisBlock worker ทำ physical writes และคืน receipts ก่อน corpus manifest เปลี่ยน

อ่านเพิ่มเติม: ภาพย่อรวม 17 stages เป็นช่วง: worker poll decision และส่ง graph/write/publication receipts กลับผ่าน MSP; Zuri import evidence ตาม cursor. Stage 13 มี physical write ก่อน 14, แล้ว 15/16, และ Stage 17 เท่านั้นที่เปิด publication. Corpus manifest เป็น immutable read-set ของ verified snapshots ไม่ใช่ GKS fact store.

FLOW 07 · DATA FLOW

ถาม published corpus และคืน citation

คำถามที่ผ่าน ACL ปัก snapshot manifest เดียว แล้ว MSP relay ไปยัง worker ซึ่งอ่าน snapshot ที่แน่นอน ก่อนตรวจ lineage และสิทธิ์อีกครั้งเพื่อคืน citation

อ่านเพิ่มเติม: ทุก query ใช้ corpus snapshot ที่ pin ไว้และ recheck ACL/revocation ก่อนตอบ; citation ชี้กลับไปยัง source/version/lineage. การ query GKS ใน LINE เป็น account mode ที่มี status แยกจาก API/MCP knowledge query.
