## Runtime architecture

- Next.js App Router pages and handlers live in `src/app/`.
- Business product-domain registration is centralized in `src/config/domains.js`.
- Business visibility is derived server-side from trusted viewer/Membership state.
- Domain application services live under `src/modules/<domain>/application/` and
  shared integration primitives live under `src/platform/integrations/`.
- SQLite is the default local authority. Postgres is a generated parity target.
- `AuditEvent` is the established append-only mutation evidence seam.
- `FileAsset` means managed file content. It cannot be renamed or reused as a
  physical-asset aggregate.
- Backup/restore is an explicit model allow-list; every new persisted model must be
  added to that contract or excluded with a written reason.

## Risks carried into Phase 2

1. There is no enumerated Procurement, Finance/Accounting or physical Inventory
   runtime module, so Asset Management cannot call or write an authority that does
   not exist.
2. `Project Inventory` is an existing read model, not a physical inventory writer.
3. LINE receives event metadata in zuri-ai, but the current transport contract does
   not fetch or deliver attachment bytes.
4. The existing shared pipeline ledger is definition-neutral; Asset intake needs a
   new definition and execution contract, not reuse of the knowledge-pipeline ID.
5. New Prisma models must preserve SQLite/Postgres parity and backup completeness.
6. Global IDs must be re-enumerated immediately before Phase 3 allocation.

## Exit decision

Phase 1 is complete and green. Proceed to Phase 2 ownership, threat, surface and
file-impact analysis.
