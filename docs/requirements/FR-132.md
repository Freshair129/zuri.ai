# ZAI:FR-132

<!-- canonical-row:start -->
```text
| FR-132 | Ladder quotation on the LINE surface, as a Gate E read-only tool: a customer asking for a price inside an existing LINE conversation ("ขอใบเสนอราคา", "คำนวณราคา TDD03-2 จำนวน 100 ชิ้น") gets a tiered quotation in the reply, and this declares **no route, no model, no converter and no credential**. (a) It adds nothing to the intake path because that path is already complete. The FR-028 webhook receives an already-verified, already-normalized batch from `zuri.command-agent`; `normalizeLineWebhookEvent` already converts every event onto the FR-081 ingestion envelope; `handleAgentTurn` already runs the turn. CR-005's `/api/connectors/line-oa/[businessId]` is refused as the second write path BR-009 and SDD-009 forbid by name — and so is the *converter* a first reading of that refusal implies, because the converter exists and has since FR-081. What is missing is one descriptor in `defaultReadOnlyTools`, which registers cleanly at Gate E precisely because a quotation computes and writes nothing (`createToolRegistry` rejects any descriptor whose `readOnly` is not `true`). (b) The reply is **returned** to the sole transport owner, never sent: BR-011 gives `zuri.command-agent` signature verification and the Reply API, and FR-050 gives this repository at most one reply text per event and no `replyToken`. The LINE Flex Message of CR-005 §3.B.2 is therefore the transport's rendering of the answer this repository returns, not something this repository posts — the boundary FR-128 already keeps for the Daily Sales Brief. (c) CR-005 §4's two invariants are both kept, and split by who may see them: rounding up to the nearest 10 THB is part of the quoted number and belongs in the reply, while the margin floor is a cost-side test applied before the number is returned and never carried in the payload, because FR-047 excludes margin from what this surface may read. A quotation that showed its own floor would breach that exclusion in the one place a customer is reading. (d) Authorization is the registry's own: `requireToolAuthorization` resolves `{tenantId, businessId, principalId}` from the turn's AuthContext and calls `authorizeScope`, so a quote is priced from the asking Business's rate card and from no other. (e) An MCP tool as CR-005 §3.B.3 proposes is a **different surface, not this one**, and is neither refused nor part of this requirement: `/api/mcp` is a viewer-authenticated back-office transport whose registry (`TOOL_DEFINITIONS`) shares no code with the in-process Gate E registry a LINE turn binds. Reworked from CR-005 | 🔜 declared only — blocked on FR-131, which is what a quotation would price against, and on intent recognition, which is undeclared: `docs/domains/agent/intent-pipeline.md` is `Status: Draft — not implemented`, nothing today turns "ขอใบเสนอราคา" into a tool call, and whether that is a model-selected tool or a matcher is an unmade decision rather than an unwritten function |
```
