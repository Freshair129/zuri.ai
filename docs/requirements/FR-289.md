# ZAI:FR-289

```text
| FR-289 | Official FlowAccount MCP connector: Support only the fixed official HTTPS endpoint through provider-verified OAuth and a documented MCP protocol/version; unverified transport, metadata, scopes, tool schemas, or company identity returns a typed unavailable result without guessed requests or REST fallback. Resolve the authenticated viewer and Business server-side, bind exactly one provider-selected company to one Business, and use the existing credential-write guard. OAuth state is short-lived, hashed, single-use, and bound to actor, tenant, and Business; the callback validates current ownership and scope and atomically consumes unexpired state before code exchange or credential storage; mismatch, replay, expiry, or a concurrent loser causes no provider request or credential write. Store access and refresh material only as a distinct FLOWACCOUNT_MCP_OAUTH_TOKEN through SecretStorePort; do not reuse OAUTH_CLIENT or NOTION_OAUTH_TOKEN, and fail closed if the typed store is unavailable. Capability discovery persists a bounded redacted manifest and exact schema digest but grants no authority; the read allow-list starts empty, and execution requires a reviewed exact tool identifier and schema digest. Deny unknown or mutating tools, including create, edit, delete, status, payment, and attachment, regardless of provider annotations. Ingest mapped reads only through FR-081 into RawExternalRecord, paired with an immutable Integration-owned FK sidecar carrying the reviewed capability identifier, manifest and tool-schema digests, trusted scope, and correlation. Commit raw and provenance rows atomically; idempotent replay validates and returns the matching pair, while orphaned or mismatched provenance fails closed and is quarantined. Do not overload sourceUri, entityType, schemaVersion, or payload for capability provenance. Safe audit events link the correlation without secrets or raw provider payload. Disable all live tool calls and live payload persistence until separate reviewed provider access, verified exact provider contract, and privacy/data-lifecycle acceptance define purpose, data categories, isolation, retention/deletion, erasure through raw and derived records, legal holds, and backup/export/restore. Local fixture tests cover state, binding, transport bounds, host/redirect rejection, allow-list and mutation denial, secret redaction, atomic provenance, idempotent replay, audit, and disconnect without contacting FlowAccount. Results remain external evidence, not accounting-domain truth or completeness; no production or Supabase change is included. | planned |
```
