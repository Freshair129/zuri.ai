## Implementation boundary — 2026-10-04

The pinned FR-057 row describes API-010 authorization before API-009 private
episodic-memory retrieval. API-011 `msp_thread_*` session context is a separate
memory tier under [ADR-091](../decisions/ADR-091-CHAT-RECORD-AND-AGENT-MEMORY-SPLIT-AND-THE-CONTEXT-COMPOSER.md);
it does not satisfy the API-010 caller requirement. See the [FR-057 plan](../roadmap/PLAN-FR-057-AUTHORIZED-AGENT-CONTEXT.md)
for current wiring evidence and activation gates. The canonical source row and
its identity remain unchanged.

### Owner-selected scope source — 2026-10-04

For each LINE OA account, an authorized Publisher selects one Development
`Project` as the API-010 episodic-memory scope. Zuri stores that project
association on the account, derives `workspaceId` from the persisted Project,
and validates the Project and Workspace against the account's tenant and
business. Admission snapshots both IDs on the job. The current mapping must
still match before API-010/API-009; a missing, deleted, archived or mismatched
scope fails closed. Workspace is never separately selected, and no LINE,
customer, model or stale session field can supply either ID.

This Project is a memory-scope association only; it does not replace the LINE
Studio's `LineOaAccount` aggregate in [ADR-060](../decisions/ADR-060-LINE-OA-STUDIO-DOMAIN-AND-MULTI-ACCOUNT-BOUNDARY.md).
Episodic access additionally requires the immutable per-job opt-in, current
Customer consent `GRANTED`, verified identity, and `DIRECT` audience.
