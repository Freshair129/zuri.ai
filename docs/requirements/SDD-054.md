| SDD-054 | Password reset splits into an authenticated mint leg and a public consume leg because token delivery, not token math, is the hard problem: with no mail transport, "who hands the secret to the user" must be a person with standing authority, so mint reuses FR-038's boundary (owner of a Business the target belongs to, or the installation operator) and returns the raw token exactly once. Storage is digest-only in the existing `PasswordResetToken.token` column (no schema change — a digest is a string), lookup is by digest so the raw value never reaches a query or log, failure is one generic `INVALID_OR_EXPIRED_TOKEN` across unknown/used/expired, and consumption revokes every active FR-095 Session in the same breath — a stolen session must not survive the reset that exists to evict it. | FR-104; FR-038, FR-046, FR-095, SEC-008, SEC-014, SDD-052 |
