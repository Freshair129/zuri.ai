| FR-119 | Per-stage failure attribution and BR-022 quarantine: a document that fails partway through the seven Tier 1 stages is quarantined with the complete failure envelope — `job_id`, `artifact_id`, `stage`, `error_code`, `error_message`, `retry_count`, `first_failed_at`, `last_failed_at`, `pipeline_version` — and classified retryable / non-retryable / review-required, rather than reported as nothing having happened. `runKnowledgeIngestionStagesWithTrace` extends FR-118's composition to catch each stage individually and report which succeeded before the one that did not, sharing every field mapping with the original throwing function (SDD-072) so neither duplicates the other. Every Tier 1 stage failure classifies `NON_RETRYABLE`: the seven stage functions are pure and deterministic, so a thrown validation error repeats identically on retry, and `REVIEW_REQUIRED` has no trigger either — an ambiguous value already declines via `canonical: null` (FR-114, SDD-061) rather than throwing, so it never reaches quarantine. `RETRYABLE`/`REVIEW_REQUIRED` stay in the vocabulary for failure modes this repository does not yet have (a network call, Tier 3/4 reporting) rather than being deleted for lack of a current trigger. | ✅ implemented 2026-08-28; 15 unit tests, 8 real-database integration tests |
