# ZAI:SDD-095

<!-- canonical-row:start -->
```text
| SDD-095 | `AuditEvent.tenantId`, `.businessId`, `.reason`, `.beforeJson`, `.afterJson`, `.requestId`, `.sessionId` are nullable columns indexed by `(tenantId, occurredAt)`, `(businessId, occurredAt)` and `(actorId, occurredAt)`, and every `recordAudit` parameter that fills them is optional. `listAccessHistory` reads a Business/Tenant scope by those columns and a person scope by joining through `Membership`/`RoleBinding` ids instead, because a grant's `entityId` is the grant's own id, not the person's, and a redundant `personId` column would only duplicate what those two tables already answer. `actorId` stays a plain UUID; resolving it to `{ id, code, displayName }` happens at read time, the same choice ADR-077 already made for `grantedByPersonId`/`revokedByPersonId`. | FR-198, FR-199; ADR-080 D1/D2/D3 |
```
