| FR-124 | Product Readiness: one read-only Platform surface at `/platform/product-readiness`, with a stable drilldown at `/platform/product-readiness/[domain]`, that answers four questions separately rather than collapsing them into one green number — how much evidence-backed implementation exists, which requirements are actually verified, whether a complete feature is ready to use, and what a Human can use it for. It renders the committed `docs/.domain-state.json` projection and nothing else: no database model, no runtime write path, no scheduled poll, no external API. **Readiness is not progress.** A feature is ready only when every underlying FR is verified and, for an explicit FEAT bundle, the registry says `live`; a 100% implementation score therefore still reads not-ready when the registry says `building`, and the surface always prints both numbers with the blocking reason. Progress itself is weighted 20% declaration + 40% code + 40% test — **a policy choice, not a derived fact**, held in one named constant (`PROGRESS_METHODOLOGY` in `scripts/domain-state.mjs`), printed beside the numbers in the UI and carried in the snapshot, and awaiting owner sign-off rather than inheritance. Projection is complete by construction: every FEAT bundle and every unbundled FR appears exactly once with one hand-written use case, and missing, duplicate, unknown or use-case-less metadata aborts graph generation, because a partial list is a wrong answer. The surface resolves its viewer on the server before rendering, so the snapshot never reaches an unauthorized browser through the RSC payload. | ✅ implemented and tested; the 20/40/40 weighting is declared and visible but not yet ratified by an owner |
