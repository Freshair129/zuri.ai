```text
| SDD-037 | Import authorization is decided **once, on the resolved target Workspace**, in the pipeline that resolves it — not in each of the three route handlers, which is how three copies of a predicate drift. `authorizeImportTarget(viewer, workspace)` is the single entry point, it calls `ownsBusiness` rather than re-deriving ownership, and it is a required argument: a caller that omits the viewer throws at the call, in the manner `classify()` now requires its `scope`, so a fourth intake surface cannot be wired up unauthorized by simply not passing it. A Workspace above Business is refused rather than governed. The refusal is **evidence-backed, not conservatism**, and its justification is deliberately stated in two tenses because the first one expires. **Until FR-067 ships:** `Membership` is created in exactly two code paths and both set `businessId`, and the viewer contract exposes only Business-keyed grants (`visibleBusinessIds`, `ownedBusinessIds`, `domainsByBusinessId`) — so no principal can hold portfolio or tenant authority at all, and any rule written for it would be untestable, satisfiable by nothing and deniable of nothing. **Once FR-067 ships that premise is false and the refusal survives on a different, stronger reason:** a `WorkspaceMembership` is *collaboration* scope on the top-level container (keyed by `portfolioId`), and FR-067 AC-067.5 makes Tenant/Business/**Space**/Project assignment a separate audited mutation requiring the relevant owner authority — so holding it confers no write authority over a Space belonging to that Portfolio. AC-067.4 says the same thing from the read side: membership alone returns no hidden Project data, and import *creates* Project data. Two further facts make this more than a technicality — a portfolio-scoped Space carries **no `tenantId`** (`prisma/seed.js` WS-PLATFORM sets only `portfolioId`), so it sits above the BR-001 isolation boundary, and one Portfolio spans every Tenant beneath it. Opening a write path there on portfolio-level membership would put a write above the boundary the whole scope chain rests on. What would legitimately unlock it is neither FR-067 nor a looser predicate: it is a Space-level owner authority carried in the viewer contract — the FR-061 shape again — after which `AUTHORIZERS` gains an entry, never before. Inventing a rule at the end of a security fix is how the fix becomes the next incident. The three routes leave `docs/.route-viewer-baseline.json` when this lands; the baseline shrinks, it is never edited to accommodate them. | FR-065; FR-012, FR-019, FR-043, BR-001, BR-009, SEC-001, SEC-002, SEC-008, SDD-009 |
```
