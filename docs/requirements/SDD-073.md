# ZAI:SDD-073

<!-- canonical-row:start -->
```text
| SDD-073 | `errorRef` on the pipeline event envelope is a reference to an error, never the error itself, and the contract now enforces the shape rather than trusting the caller. FR-071 states the redaction rule four times — `PipelineStep`/`PipelineRecordEvent` as "one redacted record outcome per attempt", the "redacted append-only evidence outbox", keeping "restricted document payloads separate from redacted pipeline events", and AC-071.28's "emit only append-only, redacted" events — and enforced it nowhere: the field was `z.string().trim().min(1).max(1000)`, which accepts a stack trace, an exception message or a quoted document fragment, on a ledger that is append-only and therefore cannot take a payload back. The rule lived entirely in caller discipline at a moment when BR-022 was about to make the field carry real failure text for the first time. `errorRef` is now a reference token — ASCII alphanumerics plus the separators a handle uses, capped at 200 — which every value in the repository already satisfied (`err://event-1`). The rule is an ALLOWED ALPHABET rather than a rejected separator on purpose: rejecting whitespace reads as sufficient in English and is not, because Thai does not separate words with spaces, so a whole Thai sentence is one whitespace-free token and would have passed a space/newline check untouched — in a product whose user-facing copy is Thai, that is the likelier shape of a real error message, not the exotic one. Stated as a bound rather than a guarantee: this blocks the accident — passing `err.message` or `err.stack` straight through — and not a determined caller, who can still join a sentence with underscores; a conforming value is not evidence that the reference carries nothing sensitive. The full human-readable message belongs in the caller's own return value, never on the shared ledger. | FR-071 AC-071.28; SEC-003; ADR-030 D2-D4 |
```
