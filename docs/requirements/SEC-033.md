| SEC-033 | Resolving a secret reference under an incorrect `secretKind` fails exactly as resolving it against the wrong store already fails (SEC-030) — no distinguishable error between "wrong kind" and any other scope mismatch — and a connectionId already holding a credential of one kind refuses a write of a different kind before any secret reaches a store, in both the envelope store and the Supabase Vault SQL functions added for `OAUTH_CLIENT` and `MODEL_PROVIDER_KEY`. This second guard is not yet extended to `zuri_core.channel_secret_write` (`LINE_CHANNEL`) in the opposite direction, since that function is live in production and untouched by design; the residual gap is accepted because nothing in the application writes a non-LINE kind at a connectionId already provisioned for LINE_OA today. | FR-242 / ADR-089 §4.8 phase 7 security gate |
