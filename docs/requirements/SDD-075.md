```text
| SDD-075 | An approval gate's evidence goes in `PipelineGateDecision.evidenceJson`, not in typed columns on the shared ledger. The column has existed since FR-071 in both `prisma/schema.prisma` and `supabase/migrations/20260820221703_smartgift_pipeline_tracking.sql` (`text NOT NULL DEFAULT '{}'`, under FORCE ROW LEVEL SECURITY with the other five tables) and nothing has ever written it: `zGate` is a five-field `.strict()` object with no evidence member, `recordPipelineEvent` passes the literal `'{}'`, and `gateSummary` drops the field from the read model — so the evidence column is present, tested for existence, and unreachable. That is the same "column present since FR-071, unwritten by anything" shape SDD-070 found on `PipelineStep`, and it takes the same fix: one optional member on the event envelope, persisted only when a caller actually supplies it, so every existing decision row and every existing caller is unchanged. Adding `catalogVersion`, `vaultId`, `approvedAt` and `approvedBy` columns as CR-003 proposes was rejected on the ledger's own terms. SDD-066 made these six tables definition-neutral precisely so a second pipeline definition could share them; `catalogVersion` is one definition's vocabulary, and putting it in a table both definitions write is the union-catalog mistake SDD-066 already refused, relocated from the validator into the schema where no validator can refuse it. `approvedAt` and `approvedBy` are additionally redundant — the `APPROVED` row's own `createdAt` and `decidedByPersonId` are those two facts, and a second copy of a fact is a second answer to it. `vaultId` is resolved per API-010 from scope (FR-057, ADR-022) and is not the ledger's to hold. The cost is named rather than hidden: `evidenceJson` is untyped `text`, so gate evidence is exactly as checkable as the Zod member that writes it and no more — which is why that member is a declared part of this decision instead of left for the first caller to invent, and why a reader must not infer a schema from a sample row. | FR-129; FR-071, FR-110, SDD-042, SDD-057, SDD-066, SDD-070, ADR-030 |
```
