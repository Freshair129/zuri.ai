| FR-142 | Deployment liveness probe and public-origin abstraction (ADR-058): `GET /api/health` answers without a session, runs exactly one trivial query (`SELECT 1`) against the configured application database, and returns `{status:'ok', db:'ok'}` with 200 or `{status:'degraded', db:'unreachable'}` with 503 — states, counts and timings only, never an error message, host or credential (SEC-009). It is the probe Docker Compose uses to mark the `web` container healthy and to start ngrok only after it. The deployment's public origin is one run-time variable, `PUBLIC_BASE_URL` (`src/lib/public-base-url.js`: `PUBLIC_BASE_URL` → build-time `NEXT_PUBLIC_APP_URL` → `http://localhost:3100`, reduced to an origin; a non-HTTP or unparsable value is ignored, not propagated); the root layout's `metadataBase` and the Platform Integrations pairing payload and LINE webhook URL derive from it or from the origin the page was actually served from — no platform hostname is assumed anywhere. | 🟠 implemented 2026-09-03 — `src/app/api/health/route.js`, `src/lib/public-base-url.js`, `tests/unit/fr142-health-route.test.js`, `tests/unit/public-base-url.test.js`; Docker Compose + ngrok stack (`Dockerfile`, `docker-compose.yml`, `docs/deployment/docker-ngrok.md`) built and run locally against the bundled Postgres profile |
