# ZAI:SDD-066

<!-- canonical-row:start -->
```text
| SDD-066 | A pipeline definition is a registry entry, and a stage id is validated against its own definition's catalog rather than against the union of every catalog. FR-071 pinned `dataPipelineDefinitionId` and `executionContractId` with `z.literal` and refined `pipelineStageId` against one ten-entry list; SDD-057 named the parameterization this slice inherits, and this decision fixes its shape. `PIPELINE_DEFINITIONS` maps a definition id to its execution contract id and its own frozen stage catalog, the envelope validates the PAIR so a run may not claim `DPL-KNOWLEDGE-INGEST-V1` under `EXC-DATA-MIGRATION-V1`, and `createPipelineRun` materializes the catalog belonging to the run's own definition instead of the one constant it happened to import. Validating a stage against the union was rejected as the easier change: it would let a Supabase migration run report a `DPS-KI-EMBED` step and pass every check, which is the ADR-050 D3 tier boundary being crossed inside a validator that reported no problem. The ten `DPS-*` ids keep their catalog and their meaning; the seventeen `DPS-KI-*` ids get their own. | FR-109; FR-071, SDD-042, SDD-057, ADR-030, ADR-050 |
```
