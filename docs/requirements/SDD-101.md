# ZAI:SDD-101

<!-- canonical-row:start -->
```text
| SDD-101 | A store's bundle validation, canonical serialization and display-hint computation are dispatched through one explicit map keyed by `secretKind` — never a boolean flag or an `if` chain — matching the `ZERO_PII_POLICY_BY_PROVIDER` dispatch style already used for zero-PII policy selection. A `secretKind` absent from the map is refused (`CHANNEL_SECRET_KIND_UNSUPPORTED`) rather than silently accepted; a model-provider API key has no non-secret identifier at all, so its display hint is always null, never a partial reveal of the key itself, distinct from the LINE channel ID / OAuth client ID convention of showing the identifier's last four characters. Before either store treats an existing credential row as a rotation target or a dead row to replace, it compares the row's stored `secretKind` to the kind being written and refuses (`CREDENTIAL_KIND_MISMATCH`) on a mismatch, so a connectionId's kind cannot drift underneath its credential by a plain write. | FR-242; SEC-030; ADR-089 §4.8 phase 7 |
```
