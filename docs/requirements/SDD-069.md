| SDD-069 | The ledger-writing wiring binds one artifact identity to one run to one document's worth of evidence, and every event's idempotency key is derived from that identity alone — never from the caller's `documentId`. `ingestKnowledgeDocument` writes a `RECORD_STARTED` / `RECORD_SUCCEEDED` pair (`docId` bound to `documentId`) around a `STEP_STARTED` / `STEP_SUCCEEDED` pair per Tier 1 stage, using the `PipelineStep` rows `createPipelineRun` already materializes from `KNOWLEDGE_INGESTION_STAGE_CATALOG` — no second step is created. The run is never marked finished: nine of the seventeen catalog steps belong to GKS and GenesisBlockDB (ADR-050 D3) and this repository does not execute them, so sending `RUN_FINISHED` here would claim a run seven-seventeenths done is complete. A stage failure inside FR-118's composition is not caught, classified or written as `STEP_FAILED` — the composition is one synchronous call with no partial result, so nothing at this layer can name which of the seven stages threw without restructuring FR-118's contract, which this slice does not do; the already-registered run stays at `QUEUED` with every step `NOT_STARTED`; an honest "attempted, nothing recorded" rather than a guess. The whole function is resumable by construction: replaying it with the same artifact replays every event's own idempotency check (FR-071) rather than needing a resume branch of its own. | FR-109; SDD-066, SDD-057, SDD-067, BR-021, ADR-050 D4 |
