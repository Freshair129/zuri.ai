```text
| SDD-090 | The located ledger and the two WIP work orders are additive columns plus four tables, never a second stock system: `WarehouseLocation` and `StockReservation` are new Business-scoped rows; `CustomizationWorkOrder` and `KittingWorkOrder` are new work-order rows that hold *intent and progress* while the FR-155 ledger keeps holding *fact*, so a work order can be queried for "how many are on the laser bench" without any quantity being stored twice. Every addition to an existing table is nullable or defaulted (`StockMovement.sourceLocationId`, `targetLocationId`, `costSatang`, `customerId`, `salesOrderId`, `workOrderId`; `Product.itemKind`, `dedicatedCustomerId`, `dedicatedSalesOrderId`, `maintenanceIntervalDays`, `maxStorageDays`, `flowAccountSku`; `ProductLot.lastMaintainedAt`; `ProductRecipe.scrapAllowanceFactor`), so every row and every reader written before this change stays correct. Work orders write the ledger only through Inventory's own `appendMovement`, which is what keeps append-only, FEFO, insufficient-stock refusal and one audit row per movement true for WIP as well. | FR-174..FR-180; ADR-074 |
```
