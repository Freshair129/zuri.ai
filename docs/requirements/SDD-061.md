# ZAI:SDD-061

```text
| SDD-061 | A normalizer that cannot decide reports the ambiguity instead of resolving it — and reports it by withholding the canonical value, not by attaching a warning beside one. A warning next to a readable field is a warning somebody skips: if `canonical` holds a guess, a caller will use it. So an undecidable value returns `canonical: null` with the reason, and the caller has nothing else to read. The case that sets the rule is a Thai date like `25/8/26`, which is 2526 BE or 2026 CE with nothing in the string to separate them — forty-three years apart, both plausible, and no downstream check can catch the wrong one. The same withholding covers an undeclared field order (`5/8/69`, where day and month are both twelve or under) and a date that does not exist (`31/2/2569`, which must never roll into March). Six of §9's twelve categories are normalized; currency, unit, product code, country/region, timezone and identifier format are declined for a stronger reason than missing locale data — their canonical form is business-configured, so one invented here would be wrong in a way that looks authoritative. | FR-114; FR-109, FR-113, SDD-060, BR-021, ADR-050 |
```
