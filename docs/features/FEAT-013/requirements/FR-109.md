```text
| FR-109 | Seventeen-stage knowledge ingestion stage catalog and job trace: the path from a source artifact to published, retrieval-ready knowledge is registered as ONE governed pipeline definition (`DPL-KNOWLEDGE-INGEST-V1`) carrying the seventeen stable stage ids of the 17-Stage Knowledge Ingestion Specification, recorded on the FR-071 execution ledger rather than on new models (SDD-057). Every ingestion occurrence is traceable end to end from a single `pipeline_job_id` — Source → RawArtifact → ParsedArtifact → Chunks → Entities → Facts → Graph → Indexes → Published Snapshot (spec §33) — with per-record disposition on `PipelineRecordEvent`, whose already-present `docId` / `picId` / `factId` columns are what that trace binds to. Sequence is documentation; the stage id is the key, exactly as FR-071's catalog already treats it, so inserting a stage never renumbers the evidence of a run that predates it. This requirement declares the catalog, the trace and the monitor: zuri-ai records ingestion and holds its gate decision, and never executes the stages ADR-050 assigns to GKS or GenesisBlockDB (ADR-043 D2.1, ADR-046). | 🟠 product-wide partial; isolated GenesisRAG17 implemented under ADR-073 (2026-09-07), documentation reconciled 2026-09-08. The existing FR-071 catalog/ledger is reused; seven separate lineage/batch/evidence/cursor/receipt models add immutable raw → parsed → chunk storage, one Stage 9 batch per attempt, all six wire metrics and exact-attempt import. Actual GKS 9–14 plus GenesisBlock physical 13/15/16 and receipt-backed 17 run through MSP. Duplicate delivery, replay, late evidence, restart lineage and source-to-published citations are covered in the [acceptance report](../.brain/reports/GENESISRAG17-ACCEPTANCE.md). The [stage flow](KNOWLEDGE-INGESTION-17-STAGE-FLOW.md) maps extension points; the FR note preserves earlier AC/slice history and broader product gaps. No production deployment or complete product-wide AC claim. |
```
