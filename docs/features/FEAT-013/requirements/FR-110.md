| FR-110 | Published knowledge snapshot contract: knowledge becomes readable only as a whole, identified publication — `knowledge_snapshot_id` with `tenant_id`, `business_id`, `ontology_version`, `pipeline_version`, `published_at` and object statistics (spec §25) — so a consumer can name the corpus an answer came from and two answers can be compared for whether they read the same one. Publication is atomic: a partially built index is never exposed to retrieval (spec §24), and only a Stage 17 gate result of `PASS` or `PASS_WITH_WARNINGS` may publish, while `QUARANTINE` and `FAIL` may not (spec §23). Zuri-AI consumes snapshots and records the publish-or-quarantine decision; it does not build the indexes a snapshot names (ADR-050; ADR-042 D2). | 🟠 product-wide partial; legacy strict snapshot/reporter/pull contracts remain. ADR-073 isolated acceptance additionally verifies GKS five-dimension gate, native worker atomic publication, scoped MSP query/citations, retained historical snapshots and finish requiring the exact publication receipt. Quality PASS without policy permission or receipt cannot close success. The new genesisrag17.v1 receipt/query profile is distinct from the full legacy snapshot/GraphRAG readiness contract; production and broader query orchestration are not claimed. See [spec](KNOWLEDGE-INGESTION-17-STAGE-SPEC.md), [flow](KNOWLEDGE-INGESTION-17-STAGE-FLOW.md) and [recorded acceptance](../.brain/reports/GENESISRAG17-ACCEPTANCE.md). |
