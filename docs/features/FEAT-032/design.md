### [ZAI:FR-208 canonical record](requirements/FR-208.md)

> Catalogue intake resolves every item before it creates anything, and applies a previewed plan all at once or not at all — every surface (JSON, Excel, LINE) converts into one `InventoryCatalogIntake` envelope v1 (`businessId`, `source.channel` REST_API / EXCEL / LINE_OA / WEB, `source.correlationId`, 1–500 `items` each naming a SKU, its master by code with the fields to create it, and optional identifiers and unit conversions); items are validated one by one so a bad row is an INVALID item rather than a rejected envelope. The planner resolves each valid item first by its active identifiers, then by its SKU code (a merged duplicate followed to its survivor): two different SKUs are a CONFLICT; one SKU is a MATCH that only adds the identifiers and conversions it lacks and warns about every other difference, never overwriting; nothing is a CREATE that still passes the FR-201 / FR-202 / FR-203 / FR-204 guards against the catalogue and against the other rows of the batch (duplicate code, identifier, variant key or description within the batch is a CONFLICT). `POST /api/inventory/catalog-intakes/preview` persists the plan with its `planHash`, idempotent on (Business, channel, correlation) — the same payload re-previews against today's catalogue, a committed or cancelled one replays, a different payload under the same correlation is refused (`INVENTORY_CATALOG_INTAKE_CORRELATION_REUSED`). `POST /api/inventory/catalog-intakes/commit` re-plans inside one transaction and refuses a changed plan (`INVENTORY_CATALOG_INTAKE_PLAN_STALE`), any CONFLICT or INVALID item (`INVENTORY_CATALOG_INTAKE_NOT_COMMITTABLE`), an expired preview (24 hours; 30 minutes from LINE) and a cancelled one, then runs every action through the existing catalogue writers in that transaction so each keeps its own guard and audit row and any refusal rolls the whole batch back. `GET /api/inventory/catalog-intakes`, `GET/PATCH /api/inventory/catalog-intakes/[id]` (CANCEL) read and cancel. Preview and commit need Inventory write authority; reads need the `inventory` domain; refusals are the FR-072 404.

### [ZAI:FR-209 canonical record](requirements/FR-209.md)

> Excel is a converter of the catalogue intake with a template built for one Business, and it never commits — `GET /api/inventory/catalog-intakes/template?businessId=` returns a workbook whose `Products` sheet header row (row 2) is the contract, with dropdowns drawn from `enums.js`, a `Lookups` sheet of that Business's own categories and masters, and a read-me; `POST /api/inventory/catalog-intakes/xlsx` (multipart `file` ≤ 5 MiB plus `businessId`, Inventory write authority checked before the file is read) converts every non-blank row into an envelope item without judging a cell — a malformed number, an unknown policy or a `BOX12=x` conversion reaches the item schema and comes back as an INVALID row with its path — refuses only a file that is not the contract (unreadable, no `Products` sheet, a header that differs, no rows, more than 500 rows), and previews under correlation `xlsx:<sha256 of the file>` so the same bytes preview idempotently. ### [ZAI:FR-210 canonical record](requirements/FR-210.md)

> A verified staff sender adds or matches SKUs from LINE with a deterministic `#sku` command that previews before it writes — the server-owned LINE worker's answer port is wrapped so that a DIRECT-chat text beginning with `#sku` is answered by the command before the model, and every other message is answered exactly as before. The command acts only when the sender's LINE channel identity for that account is verified (FR-097) and the viewer resolved from that person has Inventory write authority in the account's Business (BR-042); for anyone else — unverified, a customer, a member without write authority, a group or room — the message falls through to the normal answer. `#sku` with `key: value` lines in Thai or English (items separated by `---`; a run of 8, 12, 13 or 14 digits under บาร์โค้ด is declared a GTIN so a typo is refused by its check digit) builds the FR-208 envelope with channel LINE_OA and correlation `line:<account>:<event>` and replies with the preview; an unknown key is reported by line number and nothing is previewed. `#sku ยืนยัน <code>` commits and `#sku ยกเลิก <code>` cancels, both only for the person who previewed; every refusal becomes a Thai reply rather than a failed LINE job, and a reply stays under the LINE limit with the confirmation or fix instruction always kept. No model output reaches a write; the adapter adds no authority (SDD-091).
