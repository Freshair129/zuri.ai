| FR-208 | Catalogue intake resolves every item before it creates anything, and applies a previewed plan all at once or not at all — every surface (JSON, Excel, LINE) converts into one `InventoryCatalogIntake` envelope v1 (`businessId`, `source.channel` REST_API / EXCEL / LINE_OA / WEB, `source.correlationId`, 1–500 `items` each naming a SKU, its master by code with the fields to create it, and optional identifiers and unit conversions); items are validated one by one so a bad row is an INVALID item rather than a rejected envelope. The planner resolves each valid item first by its active identifiers, then by its SKU code (a merged duplicate followed to its survivor): two different SKUs are a CONFLICT; one SKU is a MATCH that only adds the identifiers and conversions it lacks and warns about every other difference, never overwriting; nothing is a CREATE that still passes the FR-201 / FR-202 / FR-203 / FR-204 guards against the catalogue and against the other rows of the batch (duplicate code, identifier, variant key or description within the batch is a CONFLICT). `POST /api/inventory/catalog-intakes/preview` persists the plan with its `planHash`, idempotent on (Business, channel, correlation) — the same payload re-previews against today's catalogue, a committed or cancelled one replays, a different payload under the same correlation is refused (`INVENTORY_CATALOG_INTAKE_CORRELATION_REUSED`). `POST /api/inventory/catalog-intakes/commit` re-plans inside one transaction and refuses a changed plan (`INVENTORY_CATALOG_INTAKE_PLAN_STALE`), any CONFLICT or INVALID item (`INVENTORY_CATALOG_INTAKE_NOT_COMMITTABLE`), an expired preview (24 hours; 30 minutes from LINE) and a cancelled one, then runs every action through the existing catalogue writers in that transaction so each keeps its own guard and audit row and any refusal rolls the whole batch back. `GET /api/inventory/catalog-intakes`, `GET/PATCH /api/inventory/catalog-intakes/[id]` (CANCEL) read and cancel. Preview and commit need Inventory write authority; reads need the `inventory` domain; refusals are the FR-072 404. | 🟠 implemented locally 2026-09-13 (ADR-084 D1, D2) — `inventory/domain/catalog-intake.js` (envelope, pure planner, hashes), `application/catalog-intake-service.js`, the catalogue writers accept a transaction client (`inTx`), four handlers, `InventoryCatalogIntake` model; migration `20260913200000_inventory_catalog_intake` APPLIED on production 2026-09-13 (owner-instructed, ADR-057; rolled-back dry run first, ledger row written, effect verified: 21 columns, forced RLS, one runtime policy, runtime-only grants) and main ada5188b deployed; `tests/unit/inventory-catalog-intake.test.js`, `tests/integration/fr208-inventory-catalog-intake.test.js`, `tests/integration/fr208-inventory-catalog-intake-rollback.test.js` |
