> An audit event carries its own scope and the change it made, as columns a query can filter on rather than only fields inside `payloadJson` for whichever writer happened to include them. `AuditEvent` gains `tenantId`, `businessId`, `reason`, `beforeJson`, `afterJson`, `requestId`, `sessionId` — all nullable — indexed by `(tenantId, occurredAt)`, `(businessId, occurredAt)` and `(actorId, occurredAt)`. `recordAudit` accepts all seven as optional, so every existing caller across every domain keeps writing the identical row it always wrote; only `grantBusinessMembership` and the FR-191 lifecycle services (`suspendMembership`, `reinstateMembership`, `revokeMembership`, `offboardPerson`) are updated to fill them.
