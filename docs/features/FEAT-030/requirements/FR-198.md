| FR-198 | An audit event carries its own scope and the change it made, as columns a query can filter on rather than only fields inside `payloadJson` for whichever writer happened to include them. `AuditEvent` gains `tenantId`, `businessId`, `reason`, `beforeJson`, `afterJson`, `requestId`, `sessionId` — all nullable — indexed by `(tenantId, occurredAt)`, `(businessId, occurredAt)` and `(actorId, occurredAt)`. `recordAudit` accepts all seven as optional, so every existing caller across every domain keeps writing the identical row it always wrote; only `grantBusinessMembership` and the FR-191 lifecycle services (`suspendMembership`, `reinstateMembership`, `revokeMembership`, `offboardPerson`) are updated to fill them. Measured on production 2026-09-12: 12 `Membership` rows against 6 `MEMBERSHIP_ADDED` events, and `ROLE_BINDING_ASSIGNED` 2 / `ROLE_BINDING_REVOKED` 1 against exactly 1 surviving `RoleBinding` row — one binding disappeared with no event explaining it, because scope could only be found by scanning and parsing JSON, and only for the writers that happened to include it. `actorId` stays a plain UUID column; resolving it to a display name is a read-time join, not a write-time denormalization. | ✅ implemented 2026-09-12 — ADR-080 D1/D2; migration `20260912150000_audit_scope_and_evidence.sql`, additive-only, no precondition block. APPLIED on production 2026-09-12 |
