| FR-176 | A customization work order is the durable record of branded work in progress, and branding is irreversible — `CustomizationWorkOrder` (`CWO-YYYYMMDD-NNN`) binds one raw SKU, one technique (`LASER_ENGRAVING`, `SILK_SCREEN`, `UV_DIGITAL_PRINT`, `HOT_STAMP_FOIL`, `EMBOSSING`), one customer and one sales order, with artwork, Pantone colours, setup and run cost in satang, and issued / completed / scrapped quantities as it runs (`DRAFT → RELEASED → IN_PROGRESS → COMPLETED \| CANCELLED`, plus `BLOCKED_SHORTAGE` when scrap outruns the buffer). Releasing it transfers the gross quantity into `TH_WIP_CUSTOMIZATION`; completing it consumes the raw units, issues scrap to `TH_QUARANTINE_SCRAP` and receives a different product — `itemKind` `CUSTOM_COMPONENT` with `dedicatedCustomerId` / `dedicatedSalesOrderId` set — which the domain then refuses to issue to another customer, to transfer back into generic raw stock, or to consume for another order. The only exit is an explicit ADJUSTMENT write-off with a stated reason. | 🟠 implemented locally 2026-09-10 (ADR-074 D4) — `inventory/domain/inventory-wip.js`, `application/customization-work-order-service.js`; `tests/integration/fr176-customization-work-order.test.js` |
