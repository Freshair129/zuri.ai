| FR-197 | Operator access is time-boxed, issuable by a standing operator, and its use is recorded. `issueOperatorGrant` requires an existing `isInstallationOperator` caller, a reason and a mandatory `expiresAt` capped at 90 days; a renewal is a fresh `PlatformGrant` row, with any prior ACTIVE grant for that Person superseded (revoked, its own audit event) in the same transaction — `@@unique(personId, capability)` is replaced by a partial unique index scoped to `status = 'ACTIVE'` so the history survives. `hasOperatorGrant` honours `expiresAt` even while the row is still nominally ACTIVE; nothing flips status on a timer. The bootstrap grant is flagged `standing: true` (it predates any operator to issue it); every issued grant is `standing: false`. Reading `/api/audit` and previewing or restoring a backup now route through `assertOperatorAndRecordUse`, which writes one `OPERATOR_ACTION` audit event per successful use — a denied attempt records nothing, because the refusal happens before the write. The restore path proves authority first and records the use INSIDE its transaction, after the re-insert: a record written beforehand is deleted by the wipe it is recording — read as ADR-017 D6 covering operator READS, a deliberate extension argued in ADR-079 rather than an obvious consequence of it. | ✅ implemented 2026-09-12 — `operator-bootstrap.js`, `operator-use.js`; migration `20260912140000_access_invite_sod_operator.sql` APPLIED on production 2026-09-12 |
