| FR-191 | An access grant can be withdrawn by a named person, for a stated reason, without destroying the evidence that it existed. `Membership` carries its own provenance (`grantedByPersonId`, `grantReason`, `grantSource`, `expiresAt`) and its own end (`revokedAt`, `revokedByPersonId`, `revokeReason`), and identity exposes `suspendMembership`, `reinstateMembership`, `revokeMembership` and `offboardPerson` — each requiring a reason, each cascading to the dependent RoleBinding rows, each refusing 409 LAST_OWNER rather than leaving a Business with no live owner. A revoked grant is never deleted; a partial unique index excludes it so the same scope can be granted again as a new row. `resolveViewer` additionally denies a grant past its `expiresAt`. Authority is `ownsBusiness` for a BUSINESS-scoped grant and `ownsTenant` for a TENANT-scoped one, which makes the broadest grant in the system administrable for the first time. `Membership` is written only from `src/modules/identity/`, enforced by a preflight ratchet. HR Remove permits live OPERATOR to revoke one explicitly selected scoped grant, retaining last-owner protection; other authority is unchanged. | ✅ implemented 2026-09-12 — ADR-077 D1/D2/D8; closes the defect class in `.brain/rca/2026-09-12-a-grant-that-cannot-be-withdrawn.md`.
