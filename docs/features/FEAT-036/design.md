> Integration credential vault: a provider secret is written, rotated, revoked and resolved only through the Integration lane's `SecretStorePort`, whose writable store is Supabase Vault or the app-level envelope-encryption store chosen by `ZURI_SECRET_STORE`, with the read-only deployment secret mount kept as an operator-only adapter. Every write creates a new credential version in `PENDING_VALIDATION` that becomes `ACTIVE` only after live validation; a rotation keeps the previous version resolvable until the new one validates and then purges it, and a failed validation purges the new one instead; a revocation marks the credential `REVOKED`, purges the stored material, invalidates the runtime cache and fences the account it serves; a restored snapshot sets every credential to `REENTRY_REQUIRED`; a store write whose database transaction fails is purged by compensation and recorded. Prisma holds only the reference, store, kind, status, version history, validation outcome and a non-secret display hint (the last four characters of the Channel ID), and the resolver re-checks Tenant, Business, connection and destination from the rows, never from its arguments.

### [ZAI:FR-224 canonical record](requirements/FR-224.md)

> Credential-write step-up gate: every credential write, rotation, revocation and live validation requires a Session at assurance level AAL2 through `assertSessionAssurance(viewer, 'AAL2')` for every role allowed to write a credential, refusing 403 `ASSURANCE_LEVEL_INSUFFICIENT` otherwise and 403 `MFA_FACTOR_REQUIRED` with a link to enrolment when the Person has no ACTIVE TOTP factor. The same routes are rate-limited per Person and Business (five writes or validations in fifteen minutes, a rejected LINE validation counting twice) and per installation (sixty LINE validation calls a minute), answering 429 `CREDENTIAL_RATE_LIMITED` with `retryAfterSeconds`. An operator may suspend the step-up — and only the step-up — for an installation by setting `ZURI_CREDENTIAL_STEP_UP=off` on the server (ADR-100 D8); any other value leaves it on. While suspended, a request with no logged-in Person is still refused 401, both rate limits still apply, and every write that passes the gate is audited as `CREDENTIAL_STEP_UP_SUSPENDED` with the credential action and the setting, never a credential.

### [ZAI:FR-226 canonical record](requirements/FR-226.md)

> LINE channel account claim: one LINE bot, identified by the SHA-256 of its destination, is bound to at most one live connection across the whole installation. A connection attempt for a bot already claimed in the same Tenant answers 409 `LINE_CHANNEL_ALREADY_CONNECTED`, naming the sibling account only when the viewer may see it; one claimed in another Tenant answers 409 `LINE_CHANNEL_CLAIMED_ELSEWHERE` with a truthful Thai message that names no Tenant or Business, and only after the caller has proved possession of the channel secret. The claim is taken before any secret is stored, so a refused claim leaves no orphan secret; an operator-mediated takeover is a later requirement.
