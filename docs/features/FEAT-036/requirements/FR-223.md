| FR-223 | Integration credential vault: a provider secret is written, rotated, revoked and resolved only through the Integration lane's `SecretStorePort`, whose writable store is Supabase Vault or the app-level envelope-encryption store chosen by `ZURI_SECRET_STORE`, with the read-only deployment secret mount kept as an operator-only adapter. Every write creates a new credential version in `PENDING_VALIDATION` that becomes `ACTIVE` only after live validation; a rotation keeps the previous version resolvable until the new one validates and then purges it, and a failed validation purges the new one instead; a revocation marks the credential `REVOKED`, purges the stored material, invalidates the runtime cache and fences the account it serves; a restored snapshot sets every credential to `REENTRY_REQUIRED`; a store write whose database transaction fails is purged by compensation and recorded. Prisma holds only the reference, store, kind, status, version history, validation outcome and a non-secret display hint (the last four characters of the Channel ID), and the resolver re-checks Tenant, Business, connection and destination from the rows, never from its arguments. | 🚧 merged #398 2026-09-14 (main 2aef8caa; not deployed; migrations applied on production 2026-09-14; TASK-ZAI-078, ADR-089 D1, D2, D5, FEAT-036) — `SecretStorePort`, Supabase Vault and envelope stores, dispatching secret manager, credential lifecycle; `IntegrationCredentialVersion`, `IntegrationSecretEnvelope` and the new `IntegrationCredential` columns; migrations 20260914140000, 20260914140200, 20260914140300 applied on production 2026-09-14; write-only routes: `POST /api/line-oa/connections` (secret body), `POST /api/line-oa/connections/[id]/credential` (rotate), `…/credential/revoke`, `…/credential/validate` (TASK-ZAI-080) |
