| FR-225 | Self-serve LINE OA connection: a Business owner connects a LINE Official Account from the browser by entering its Channel ID and Channel secret — and a long-lived channel access token only as a deliberate override — in a Thai wizard. The server mints a stateless token, calls LINE's bot information endpoint to prove the pair and fill the destination, basic id and display name, takes the channel account claim (FR-226), writes the credential through FR-223 and creates the `LINE_OA` connection and a DRAFT `LineOaAccount`, with no operator and no host file. A wrong Channel ID and a wrong secret answer the same 422 `LINE_CREDENTIALS_REJECTED`; a LINE outage answers 503 and stores nothing; the response carries connection, masked credential and bot metadata only. The Studio form no longer asks for a `deployment-secret:` reference, and an account backed by the mount moves into the vault when its owner re-enters the secret. | ✅ merged #406 2026-09-14 (main 9b7d8d59; not deployed; ADR-089 D2, D3, D7, FEAT-036; TASK-ZAI-082) — `LineOaConnectWizard.jsx` (Thai wizard: step-up, inline TOTP enrolment, Channel ID/secret/token, error table) replaces the Studio's deployment-secret field; `POST /api/line-oa/connections` (already vault-capable since TASK-ZAI-080) plus `POST /api/line-oa/accounts` create the DRAFT `LineOaAccount`; a DEPLOYMENT_MOUNT-backed credential migrates via the existing rotate route (`LineOaCredentialMigrationCard.jsx`); `tests/integration/fr225-line-oa-self-serve-onboarding.test.js`, `tests/unit/line-oa-connect-wizard-copy.test.js`, `tests/unit/line-oa-connect-wizard-render.test.js`, `tests/e2e/fr225-line-oa-self-serve-wizard.spec.js` |
