| FR-224 | Credential-write step-up gate: every credential write, rotation, revocation and live validation requires a Session at assurance level AAL2 through `assertSessionAssurance(viewer, 'AAL2')` for every role allowed to write a credential, refusing 403 `ASSURANCE_LEVEL_INSUFFICIENT` otherwise and 403 `MFA_FACTOR_REQUIRED` with a link to enrolment when the Person has no ACTIVE TOTP factor. The same routes are rate-limited per Person and Business (five writes or validations in fifteen minutes, a rejected LINE validation counting twice) and per installation (sixty LINE validation calls a minute), answering 429 `CREDENTIAL_RATE_LIMITED` with `retryAfterSeconds`. An operator may suspend the step-up — and only the step-up — for an installation by setting `ZURI_CREDENTIAL_STEP_UP=off` on the server (ADR-100 D8); any other value leaves it on. While suspended, a request with no logged-in Person is still refused 401, both rate limits still apply, and every write that passes the gate is audited as `CREDENTIAL_STEP_UP_SUSPENDED` with the credential action and the setting, never a credential. | 🚧 merged #398 2026-09-14 (main 2aef8caa; not deployed; migrations applied on production 2026-09-14; TASK-ZAI-080, ADR-089 D4, FEAT-036) — `credential-write-gate.js` (factor, then the live step-up window) and `rate-limit.js` over `RateLimitBucket` on `POST /api/line-oa/connections` (secret body) and `/api/line-oa/connections/[id]/credential{,/revoke,/validate}`; migration 20260914140400 applied on production 2026-09-14; sealing the TOTP secret at rest is a separate lane |
