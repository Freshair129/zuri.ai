| FR-247 | Error tracking: `logger.exception(event, error, fields)` (`src/lib/observability/logger.js`) emits exactly as `error()` does today, fingerprints the error as `sha256(name + ':' + message + ':' + firstStackFrame)` and returns the parsed shape — `src/lib` stays free of a database dependency by existing convention. `recordErrorEvent(db, logger.exception(event, error, fields))` (`application/error-events.js`) persists it, upserting one `ErrorEvent` row per fingerprint: incrementing `occurrenceCount` and `lastSeenAt` on a repeat, leaving `firstSeenAt` untouched on the first. Only `error.name`, `error.message` (this codebase's error messages are static system codes, never interpolated user input) and `error.stack` parsed into `{file, line, function}` frames are kept; a frame that is not a `file:line` shape is dropped rather than stored. An operator reads the list grouped by fingerprint under `/control` and can mark one resolved (`resolvedAt`, `resolvedByPersonId`), after which it no longer counts as active (ADR-095 D1). | ✅ deployed (merged #433, 992f8f11) — `src/lib/observability/logger.js` (exception, parseStackFrames, computeErrorFingerprint), `modules/platform-control/application/error-events.js`, `/control/errors`; `tests/unit/observability-logger.test.js`, `tests/unit/error-events.test.js`, `tests/unit/error-events-view.test.js`; migration `20260916180000_observability_error_and_usage_events` APPLIED on production |
