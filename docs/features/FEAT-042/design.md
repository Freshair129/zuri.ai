### [ZAI:FR-247 canonical record](requirements/FR-247.md)

> Error tracking: `logger.exception(event, error, fields)` (`src/lib/observability/logger.js`) emits exactly as `error()` does today, fingerprints the error as `sha256(name + ':' + message + ':' + firstStackFrame)` and returns the parsed shape — `src/lib` stays free of a database dependency by existing convention. `recordErrorEvent(db, logger.exception(event, error, fields))` (`application/error-events.js`) persists it, upserting one `ErrorEvent` row per fingerprint: incrementing `occurrenceCount` and `lastSeenAt` on a repeat, leaving `firstSeenAt` untouched on the first. Only `error.name`, `error.message` (this codebase's error messages are static system codes, never interpolated user input) and `error.stack` parsed into `{file, line, function}` frames are kept; a frame that is not a `file:line` shape is dropped rather than stored. An operator reads the list grouped by fingerprint under `/control` and can mark one resolved (`resolvedAt`, `resolvedByPersonId`), after which it no longer counts as active (ADR-095 D1).
