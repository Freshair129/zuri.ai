| FR-230 | Chat record and agent memory split with declared retention: CRM `Conversation` and `Message` are the business record of a LINE conversation, written first in the ADR-061 admission transaction, and MSP's Tier 1 session events are the agent's conversation ledger, never the record the inbox, receipts or legal retention read; MSP consolidates a closed session into episodic and passport memory with summaries the agent lane produces, and persists nothing into GenesisBlockDB. Each copy has a declared retention class with installation defaults — raw LINE payload text 90 days, message bodies and attachments 24 months, `AgentTraceEvent` payloads 90 days, MSP session event content 90 days — that a Tenant may shorten but never lengthen. A nightly sweep tombstones content past its window, keeps envelope columns, skips rows a non-terminal LINE job references, and writes one audit event per run with counts per class. | ✅ built 2026-09-14 (ADR-091 D1, D2, FEAT-037, TASK-ZAI-089) — `TenantRetentionOverride` (downward-only Tenant override) and the nightly sweep are in the schema and code, but the sweep covers only the one retention data class crm owns, `MESSAGE_BODY_AND_ATTACHMENTS`; `RAW_LINE_PAYLOAD` (integration's `RawExternalRecord`) and `AGENT_TRACE_EVENT` (agent's `AgentTraceEvent`) are each other domain's model to sweep and remain unswept, and `MSP_SESSION_CONTENT` lives in MSP, a separate repository this codebase cannot reach; migration `20260914150400`, not applied |
