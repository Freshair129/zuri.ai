## Implementation boundary — 2026-10-04

The API-011 principal erasure worker carries a durable receipt status and asks
for `erase_vault` when the erased principal has an episodic-memory projection.
The owner decision recorded in CONVERSATION-RUNTIME-HANDOFF.md v0.3.18b and
delivered in merged PR #614 sets the unit to exactly one tenant-wide MSP erase
per `(tenant, principal, erasure request)`, including DIRECT-only memory. The
tool does not resolve a thread. Local projection receipts remain independently
traceable; one acknowledged tenant-wide request settles the affected receipts
and records MSP's erasure receipt ID. `PENDING_MSP` remains visible on the
Customer until acknowledgement. No external tier is shown as erased before
acknowledgement. This owner decision supersedes the older per-projection-receipt
call wording in the preserved requirement row; the row and its provenance are
unchanged.

FR-232 is still open: the consent-decline path does not yet perform the full
Tier-1 tombstone and knowledge-source withdrawal/correction workflow specified
above, and the external GKS review path has no wired writer here. Principal
identity erasure and retryable API-011 erasure are implemented separately from
those remaining actions.
