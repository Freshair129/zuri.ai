### [ZAI:FR-143 canonical record](requirements/FR-143.md)

> Edge-executed asset evidence extraction (ADR-059 — the pull model): a cloud-queued `AssetExtractionJob` lets the customer-premise Zuri Edge Device (ADR-041) run the FR-138 candidate extraction under its own subscription-based auth, so neither a provider API key nor any edge secret has to live in the cloud (ADR-041 D3) and the cloud never has to reach a device behind NAT. `POST /api/assets/evidence/{id}/extract` chooses the provider — `ZURI_ASSET_EVIDENCE_PROVIDER` = `openai` | `edge` wins when set; unset resolves to `edge` when no `OPENAI_API_KEY` is configured **and** the Business has at least one ACTIVE FR-144 credential, otherwise `openai` — where `openai` is FR-138 unchanged and `edge` creates exactly one QUEUED job and answers `202 { job }`. The lifecycle is QUEUED → CLAIMED → COMPLETED | FAILED, plus CANCELLED, plus lease expiry back to QUEUED, with at most one non-terminal job per `AssetEvidence`. The device claims work with the FR-144 credential: `POST /api/edge/extraction-jobs/claim` returns the oldest QUEUED job of that credential's Business under a 10-minute lease or `204` when none is queued; `GET /api/edge/extraction-jobs/{id}/evidence` streams the evidence bytes with the `FileAsset` MIME **only** while the job is CLAIMED by that device and the lease is live, never a bucket URL or storage credential; `POST /api/edge/extraction-jobs/{id}/complete` `{candidate, model}` and `POST /api/edge/extraction-jobs/{id}/fail` `{reason}` close it. The returned candidate is validated with the **same** `zCandidate` schema the OpenAI adapter uses — one shared module, so the two adapters cannot drift — and written through the same path as `extractAssetEvidence`: `AssetEvidence.extractionJson`, status `EXTRACTED`, one `ASSET_EVIDENCE_EXTRACTED` audit event carrying provider `edge`, the model the device reported and the device id. Extraction creates a candidate and never a review or an approval (BR-025 stands). `complete`/`fail` are idempotent per job `version`, a COMPLETED job is never re-claimed, and `GET /api/assets/evidence/{id}/extraction-job` gives the review surface the latest job to poll.

### [ZAI:FR-144 canonical record](requirements/FR-144.md)

> Edge device credential — `EdgeDeviceCredential`, the Business-scoped bearer credential a Zuri Edge Device presents to the cloud. It is a third, distinct credential family: FR-106's `ApiAccessKey` is Tenant-bound Enterprise API access and FR-123's `PluginSession` is a public-client plugin identity; neither is a device. A Business OWNER (`ownsBusiness`) or an installation operator mints one from LINE OA Studio's Edge Connection page (moved 2026-09-09 from `/platform/integrations`, which now carries no pairing UI of its own) with `POST /api/platform/edge-devices/credentials` `{businessId, deviceId, label}`: the raw `edgk_…` key appears **exactly once**, in the mint response, and is persisted only as a SHA-256 `keyHash` beside a display `keyPrefix`, with `status` ACTIVE | REVOKED, `lastUsedAt`, `revokedAt` and `revokeReason`. `GET /api/platform/edge-devices/credentials?businessId=` returns metadata only and `DELETE /api/platform/edge-devices/credentials/{id}` revokes; mint and revoke each write an `EDGE_DEVICE_CREDENTIAL` audit event, and a Business the caller does not own is refused with the same 404 a nonexistent Business receives (FR-072 refusal discipline). `resolveEdgeDeviceContext(request)` turns `Authorization: Bearer edgk_…` into `{ deviceId, businessId, tenantId, credentialId }` and touches `lastUsedAt`, or refuses `401` — missing, malformed, unknown, revoked and non-`edgk_` credentials are indistinguishable in the response. It is the authority for the FR-143 device routes and is additionally accepted by the FR-141 heartbeat `POST`, closing that requirement's open "device-scoped credential" item: the device context supplies `businessId`, and a `businessId` in the payload must match it or be absent. Owner-approved 2026-09-08: `/edge/pair` adds browser/QR approval through `POST /api/edge/pairing/start`, `/approve` and `/poll`: five-minute, bounded process-local requests; authenticated same-origin Business-owner approval; separate initiating-device secret; authority rechecked and existing credential minted only on one-time device redemption. Browser receives no device key; restart/expiry/cancellation requires a fresh request. The existing manual export remains compatible.
