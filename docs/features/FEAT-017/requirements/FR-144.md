| FR-144 | Edge device credential — `EdgeDeviceCredential`, the Business-scoped bearer credential a Zuri Edge Device presents to the cloud. It is a third, distinct credential family: FR-106's `ApiAccessKey` is Tenant-bound Enterprise API access and FR-123's `PluginSession` is a public-client plugin identity; neither is a device. A Business OWNER (`ownsBusiness`) or an installation operator mints one from LINE OA Studio's Edge Connection page (moved 2026-09-09 from `/platform/integrations`, which now carries no pairing UI of its own) with `POST /api/platform/edge-devices/credentials` `{businessId, deviceId, label}`: the raw `edgk_…` key appears **exactly once**, in the mint response, and is persisted only as a SHA-256 `keyHash` beside a display `keyPrefix`, with `status` ACTIVE \| REVOKED, `lastUsedAt`, `revokedAt` and `revokeReason`. `GET /api/platform/edge-devices/credentials?businessId=` returns metadata only and `DELETE /api/platform/edge-devices/credentials/{id}` revokes; mint and revoke each write an `EDGE_DEVICE_CREDENTIAL` audit event, and a Business the caller does not own is refused with the same 404 a nonexistent Business receives (FR-072 refusal discipline). `resolveEdgeDeviceContext(request)` turns `Authorization: Bearer edgk_…` into `{ deviceId, businessId, tenantId, credentialId }` and touches `lastUsedAt`, or refuses `401` — missing, malformed, unknown, revoked and non-`edgk_` credentials are indistinguishable in the response. It is the authority for the FR-143 device routes and is additionally accepted by the FR-141 heartbeat `POST`, closing that requirement's open "device-scoped credential" item: the device context supplies `businessId`, and a `businessId` in the payload must match it or be absent. Owner-approved 2026-09-08: `/edge/pair` adds browser/QR approval through `POST /api/edge/pairing/start`, `/approve` and `/poll`: five-minute, bounded process-local requests; authenticated same-origin Business-owner approval; separate initiating-device secret; authority rechecked and existing credential minted only on one-time device redemption. Browser receives no device key; restart/expiry/cancellation requires a fresh request. The existing manual export remains compatible. | superseded 2026-09-25 — ADR-110 D5 retires the EdgeDeviceCredential and pairing surfaces from active product scope. Historical implementation record: ✅ implemented 2026-09-04 (PR #213) — `EdgeDeviceCredential`, mint/list/revoke, `resolveEdgeDeviceContext`, the FR-141 heartbeat acceptance and (originally) the `/platform/integrations` Edge panel that replaced the browser-side pairing-string generator; `tests/integration/fr144-edge-device-credential.test.js` plus two unit suites. Production migration `20260904090000` applied and recorded 2026-09-04. Key rotation remains mint-then-revoke with no grace window, as declared. 2026-09-09: the manual-mint panel moved to LINE OA Studio's Edge Connection page (`LineStudioEdgeConnection.jsx`) as the one surface for it; `/platform/integrations` carries no Edge pairing UI anymore |
