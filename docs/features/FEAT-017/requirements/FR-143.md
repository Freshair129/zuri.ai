```text
| FR-143 | Edge-executed asset evidence extraction (ADR-059 — the pull model): a cloud-queued `AssetExtractionJob` lets the customer-premise Zuri Edge Device (ADR-041) run the FR-138 candidate extraction under its own subscription-based auth, so neither a provider API key nor any edge secret has to live in the cloud (ADR-041 D3) and the cloud never has to reach a device behind NAT. `POST /api/assets/evidence/{id}/extract` chooses the provider — `ZURI_ASSET_EVIDENCE_PROVIDER` = `openai` \| `edge` wins when set; unset resolves to `edge` when no `OPENAI_API_KEY` is configured **and** the Business has at least one ACTIVE FR-144 credential, otherwise `openai` — where `openai` is FR-138 unchanged and `edge` creates exactly one QUEUED job and answers `202 { job }`. The lifecycle is QUEUED → CLAIMED → COMPLETED \| FAILED, plus CANCELLED, plus lease expiry back to QUEUED, with at most one non-terminal job per `AssetEvidence`. The device claims work with the FR-144 credential: `POST /api/edge/extraction-jobs/claim` returns the oldest QUEUED job of that credential's Business under a 10-minute lease or `204` when none is queued; `GET /api/edge/extraction-jobs/{id}/evidence` streams the evidence bytes with the `FileAsset` MIME **only** while the job is CLAIMED by that device and the lease is live, never a bucket URL or storage credential; `POST /api/edge/extraction-jobs/{id}/complete` `{candidate, model}` and `POST /api/edge/extraction-jobs/{id}/fail` `{reason}` close it. The returned candidate is validated with the **same** `zCandidate` schema the OpenAI adapter uses — one shared module, so the two adapters cannot drift — and written through the same path as `extractAssetEvidence`: `AssetEvidence.extractionJson`, status `EXTRACTED`, one `ASSET_EVIDENCE_EXTRACTED` audit event carrying provider `edge`, the model the device reported and the device id. Extraction creates a candidate and never a review or an approval (BR-025 stands). `complete`/`fail` are idempotent per job `version`, a COMPLETED job is never re-claimed, and `GET /api/assets/evidence/{id}/extraction-job` gives the review surface the latest job to poll. | ✅ implemented 2026-09-04 (PR #213) — `AssetExtractionJob`, the four device routes, the review-surface read and the provider choice; `tests/integration/fr143-asset-extraction-job.test.js` (9 real-database cases: queue idempotency, oldest-first claim, cross-Business refusal, byte access under a live lease only, candidate write, schema rejection, lease expiry, attempt ceiling, device-context refusal) plus two unit suites. Production migration `20260904090000` applied and recorded 2026-09-04. The edge runtime itself lives in `zuri-edge-device` (ADR-059 D6); cancellation authority stays deliberately unanswered, so CANCELLED is unreachable from any surface  Retirement deferred in this PR: ADR-110 D1 removes the Server route and UI, but the corresponding client caller remains under apps/edge; no new Edge behavior is available through this checkout. |
```
