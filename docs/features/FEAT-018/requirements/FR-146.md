| FR-146 | LINE OA Studio account aggregate — `LineOaAccount`, the Business-scoped operating record for one LINE Official Account and the root of the multi-account command center (ADR-060 D2/D3/D5/D11). Identity: internal UUID plus a Tenant-unique human `code`; `tenantId` and `businessId` derived from the trusted viewer and the selected visible Business, never from the payload; a 1:1 reference to an existing `LINE_OA` `IntegrationConnection` (FR-080); an optional agent binding `code` (= identity's `channelAccountId`, FR-052 / FR-097); LINE channel id, basic id and bot user id are external references (BR-002), never keys. State: `status` DRAFT → CONNECTED → LIVE \| PAUSED \| ARCHIVED, where LIVE is derived from the agent lane's ACTIVE binding and can never be set by a client; `transportMode` EDGE \| CLOUD, fixed at connect time from whether the Business holds an ACTIVE `EdgeDeviceCredential` (FR-144, the ADR-059 D5 rule), overridable by a publisher at connect time and changed afterwards only by an audited, versioned switch that cancels work queued under the old owner; `isDefaultForBusiness` at most one per Business; a presentation profile (greeting, fallback text, persona label) that is configuration, not knowledge. Cardinality: any number of accounts per Business, exactly one Business per account; moving an account is a new account plus an archive. Authority: list and read require Business visibility plus the `line-oa` domain (FR-061); connect, pause, archive, default and mode override require Business OWNER or an active `LINE_OA_PUBLISHER` `RoleBinding` (FR-076 pattern); refusals are 404-shaped (FR-072). Connecting never creates, reads or returns credential material and never activates routing (ADR-020): the connection is created only through the integration lane's owner-only contract, and health (connection status and secret readiness, binding status, last webhook receipt, queued or failed transport jobs, quota) is computed read-model output, never stored. Every write is transactional, versioned and audited without secret or customer content. | 🟠 implemented locally 2026-09-05 (FEAT-018 slice 1): `LineOaAccount` in both provider schemas with additive migrations (production SQL `supabase/migrations/20260905120000_line_oa_account.sql` written, **not applied**), the only writer `src/modules/line-oa-studio/application/line-oa-account-service.js`, `GET/POST /api/line-oa/accounts` and `GET/PATCH /api/line-oa/accounts/{id}`, the `LINE_OA_PUBLISHER` role in identity's registry, the reserved (hidden `soon`) `line-oa` domain slot, and the integration lane's `readLineOaConnectionHealth` read contract; `tests/integration/fr146-line-oa-account.test.js` plus three unit suites. Not yet: the agent binding reader — `effectiveStatus` cannot reach LIVE and health reports the binding as UNKNOWN until it is wired — the `/line-oa` pages, transport jobs and quota in health. 2026-09-05 (FR-147): the binding reader is wired — `health.binding.status` is now ACTIVE / NOT_ACTIVE / NO_BINDING / UNKNOWN from the agent lane's contract, and `effectiveStatus` reaches LIVE on ACTIVE |
