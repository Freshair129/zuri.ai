> Goods receipts into the stock ledger (procurement) — `GoodsReceipt` and `GoodsReceiptLine` (ADR-066 D4/D6): a receipt with a generated `code` `GRN-YYYYMMDD-NNN` unique per Tenant, the supplier's delivery-note number as an attribute and `receivedAt`, posted only against a SENT purchase order (`PURCHASE_ORDER_NOT_RECEIVABLE` otherwise); every receipt line names one line of that order (`PROCUREMENT_RECEIPT_LINE_NOT_FOUND`, once per receipt) and may not receive more than the line still has outstanding — refused whole with the per-line list (`PROCUREMENT_RECEIPT_EXCEEDS_ORDERED`). A line whose order line names a counted (TRACKED) SKU writes RECEIPT rows into the Inventory ledger through Inventory's exported `appendMovement` inside the same transaction with reason `GOODS_RECEIPT` and reference `PO:<code>/GRN:<code>` — `lotCode` names or creates the lot (a LOT-tracked SKU needs one; Inventory's `INVENTORY_LOT_REQUIRED` bubbles up), a given `expiresAt` is set on a lot that has no expiry yet and never overwrites one, `serialNos` create the units (exactly one per unit; `INVENTORY_SERIAL_COUNT_MISMATCH` bubbles up); an uncounted SKU or a free-text line is recorded on the receipt, touches no ledger and refuses lot or serial data (`PROCUREMENT_RECEIPT_LINE_NOT_COUNTED`). The ledger half needs Inventory's write authority on top of the buyer's (`403 PROCUREMENT_RECEIPT_REQUIRES_INVENTORY_AUTHORITY`; a Procurement role never widens Inventory); a receipt of only uncounted or free-text lines needs none. The receipt that completes every line makes the order RECEIVED in the same transaction (audited on the order too); the order's `version` moves with each receipt. A receipt has no status, no version and no PATCH — never edited or deleted; a wrong one is corrected by an Inventory ADJUSTMENT. Posting needs Business OWNER or `PROCUREMENT_BUYER` (`procurement.receipt.post`); reading needs the `procurement` domain; every refusal of scope is the FR-072 404; one audit row per receipt.
