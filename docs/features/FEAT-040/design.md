## Included requirements

### [ZAI:FR-243 canonical record](requirements/FR-243.md)

> Conversation sessions: every LINE `Message` and `ConversationEvent` belongs to a `ConversationSession` of its `Conversation`, so one long-lived conversation reads as separate sittings. An inbound message joins the conversation's latest session when the previous message in that conversation is newer than the account's idle timeout, measured by message time; otherwise it opens a new session. The decision is made inside the ADR-061 admission transaction and serialized per conversation, so concurrent deliveries open one session. A reply joins the session of the inbound message it answers and never opens one; a `ConversationEvent` takes the open session or none. The idle timeout defaults to 30 minutes and each LINE OA account may set 10 to 120 minutes; there is no midnight cut. A session is closed once its last message is older than the timeout, and its `closedAt` is written when the next session opens, with no sweeper. Each session has an internal id and a human code and carries its conversation, Customer, Business, Tenant and account ids, open, last-message and close times, inbound and outbound counts and, when MSP thread memory is on, the MSP session id. `LineConversationJob` carries the session id and trace events reach it through the job's turn; the inbox shows a divider between sessions; existing messages are backfilled by the same rule.

### [ZAI:FR-244 canonical record](requirements/FR-244.md)

> Local model residency follows business hours: each LINE OA account may declare business hours in Asia/Bangkok and a fixed out-of-hours reply. The edge worker keeps the local model loaded (Ollama `keep_alive: -1`) while any account it serves is inside its hours, unloads it (`keep_alive: 0`) after the last of those accounts closes, and loads it again before the first one opens. A message that arrives outside its account's hours is answered with that account's out-of-hours reply without a model call and is recorded like any other reply. An account with no declared hours keeps the model loaded at all times, which is today's behaviour. Closing a conversation session never loads or unloads a model, because VRAM is held per loaded model, not per conversation.
