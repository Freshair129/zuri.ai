```text
| FR-244 | Local model residency follows business hours: each LINE OA account may declare business hours in Asia/Bangkok and a fixed out-of-hours reply. The edge worker keeps the local model loaded (Ollama `keep_alive: -1`) while any account it serves is inside its hours, unloads it (`keep_alive: 0`) after the last of those accounts closes, and loads it again before the first one opens. A message that arrives outside its account's hours is answered with that account's out-of-hours reply without a model call and is recorded like any other reply. An account with no declared hours keeps the model loaded at all times, which is today's behaviour. Closing a conversation session never loads or unloads a model, because VRAM is held per loaded model, not per conversation. | 🚧 built 2026-09-16 on branch `feat/fr244-model-residency` (not merged), TASK-ZAI-109 (ADR-094 D6 option A) — resolved against ADR-061's identity boundary (owner-confirmed 2026-09-16): the job-claim wire carries no account id, so the edge cannot hold a per-account schedule; instead `LineOaAccount.businessHoursOpen`/`businessHoursClose`/`outOfHoursReplyText` (migration `20260916130000`, not applied) drive two server-side things — `POST /api/edge/model-residency` returns one aggregate `shouldBeWarm` boolean across every server-enabled account, identity-free, and admission (`admitLineTextMessage`) creates the job straight at `READY` with the out-of-hours text as its answer when the account is closed, so it is sent by the existing tick worker and never reaches execution. The edge polls the directive every 60s (`model-residency-schedule.ts`) and calls the existing `warmModel`/`releaseModel` only on a change, sharing `triggerWarm`'s own in-flight guard |
```
