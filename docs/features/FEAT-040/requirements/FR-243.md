```text
| FR-243 | Conversation sessions: every LINE `Message` and `ConversationEvent` belongs to a `ConversationSession` of its `Conversation`, so one long-lived conversation reads as separate sittings. An inbound message joins the conversation's latest session when the previous message in that conversation is newer than the account's idle timeout, measured by message time; otherwise it opens a new session. The decision is made inside the ADR-061 admission transaction and serialized per conversation, so concurrent deliveries open one session. A reply joins the session of the inbound message it answers and never opens one; a `ConversationEvent` takes the open session or none. The idle timeout defaults to 30 minutes and each LINE OA account may set 10 to 120 minutes; there is no midnight cut. A session is closed once its last message is older than the timeout, and its `closedAt` is written when the next session opens, with no sweeper. Each session has an internal id and a human code and carries its conversation, Customer, Business, Tenant and account ids, open, last-message and close times, inbound and outbound counts and, when MSP thread memory is on, the MSP session id. `LineConversationJob` carries the session id and trace events reach it through the job's turn; the inbox shows a divider between sessions; existing messages are backfilled by the same rule. | 🚧 2026-09-16 (ADR-094 D1–D5, FEAT-040): assignment on admission, replies and events, the account timeout column and the backfill merged in #420 (TASK-ZAI-106, main 000b26f1); job session id, the session filter with per-job trace, the Inbox divider and the timeout setting built on `feat/crm-conversation-sessions` (TASK-ZAI-107); migrations `20260916090000` and `20260916120000` written, not applied, not deployed |
```
