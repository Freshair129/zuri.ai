### [ZAI:FR-265 canonical record](requirements/FR-265.md)

> LINE OA Studio conversation work is server-executed only. `EDGE` leaves the account's transport and execution vocabulary: `transportMode` admits CLOUD alone, `executionMode` is always SERVER, and the `SWITCH_TRANSPORT_MODE` action is withdrawn. A separate durable `LineOaAccount.runtimeOwner` defaults to SERVER; admission snapshots it onto each `LineConversationJob`, and only an opted-in conversation eligible for the Conversation Runtime may be admitted with `runtimeOwner=CONVERSATION_RUNTIME` (ADR-106 D3 and its 2026-09-27 amendment: a direct, group or room audience, from a verified or an unverified sender; an unverified sender's job runs with no person). Ineligible work stays in the SERVER cohort. Owner changes use `CONFIGURE_EXECUTION` and require the account's outstanding jobs to be quiescent; environment flags or process readiness never determine ownership. Core remains authoritative for admission, claims, leases, receipts, state transitions and side effects in both cohorts; the runtime invokes turns only through strict Core ports. The `modelAccess` LOCAL_ONLY branch is removed with EDGE: it never called a model, but substituted a deterministic canned answerer, so an account left on it replied to real customers without inference. The Edge conversation-job surface — claim, context, tools, complete, fail — and model-residency directive are withdrawn as routes; historical `LineConversationJob.executionMode=EDGE` remains readable and is never newly written. ADR-110 D1 later retires Zuri-owned device pairing, Edge credentials and Edge extraction surfaces; D3 preserves existing records and schema.

### [ZAI:FR-267 canonical record](requirements/FR-267.md)

> A Business owner may choose the operator's Private Runtime Platform (PRP) as the model provider for its LINE answers, so a customer's message is processed on the operator's own GPU and reaches no external provider: provider code `prp` on the FR-266 route, offered only when the operator has configured the runtime's base URL on the server (`ZURI_PRIVATE_RUNTIME_BASE_URL`, HTTPS, no credentials, query or fragment) and never an endpoint a browser can supply. The Business's PRP client key is proved against PRP's `GET /v1/models`, which lists the model aliases granted to that key: 401/403 refuses the key, a chosen alias absent from the list refuses the model, and nothing is stored on either. Answers use PRP's OpenAI-compatible `POST /v1/chat/completions`; a reasoning block the model emits (`<think>…</think>`) is removed before the text can reach a customer, and an answer that is only an unfinished reasoning block fails closed rather than being sent. PRP's own "no eligible node" and deadline refusals fail the answer — there is no fallback to an external provider.
