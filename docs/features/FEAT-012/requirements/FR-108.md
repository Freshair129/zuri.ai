| FR-108 | ExecutionPlanBundle import orchestration: the self-contained multi-Project planning package above PlanEnvelope (ADR-049; normative schema `contracts/execution-plan-bundle.schema.json`) becomes importable end to end. A Bundle Import Orchestrator in the project-manager intake lane coordinates EXISTING application services only — it writes no table directly and creates no second PlanEnvelope writer (BR-009). Scope is resolved from the trusted viewer before any sensitive parsing or preview (ADR-049 D5 — previewing another tenant's plan is refused exactly as a write would be); bundle schema and bundle-level semantics validate; strategy (Roadmap/Horizons/Goals) dry-runs; bundle-local symbolic refs resolve to canonical UUIDs inside the authorized scope and fail closed on unknown, ambiguous, cross-Business, cross-Workspace or type-mismatched targets, granting no authority (D4); every Project entry runs the EXISTING PlanEnvelope dry-run; cross-Project dependencies validate against the combined preview; and one combined preview precedes one explicit confirmation — any unresolved conflict keeps the whole bundle non-committable (D7). Surfaces `POST /api/import/bundle/dry-run` and `POST /api/import/bundle/commit`; every transport converges on the orchestrator (D3). Bundles are data only — nothing arriving in one is ever executed (BR-007, SEC-002, D6). | ✅ implemented 2026-08-27 — agent lane |
