| FR-156 | Inventory recipe / bill of materials at a batch size — `ProductRecipe` (`recipe_id`: `code` unique per Tenant, one row per output SKU and `batchSize` — "the recipe for 10 seats" and "for 20 seats" are two rows on one product, exactly as a gift box has a BOM at 10 / 50 / 100 / 500 sets — with `yieldQty`, `unit`, `notes`, ACTIVE / ARCHIVED, `version`) and `ProductRecipeLine` (a same-Business component SKU with `qty` per batch, optional `unit`, `fixed` for a line that does not scale with the quantity built, such as tooling; a component appears once and is never the output). Pure calculators pick the recipe for a quantity (the largest batch size that fits, else the smallest), explode it (scaled lines multiply by `quantity / batchSize`, fixed lines do not, the output yield follows the batch), compare with on-hand recomputed from the ledger (a fractional requirement is issued as the next whole unit; an uncounted component never blocks) and state the maximum buildable quantity. `GET /api/inventory/recipes/[id]?quantity=` returns that explosion; `POST …/build` is one transaction that issues every counted component through the FR-155 ledger (FEFO for lots) and receives the output SKU when it is counted — refused whole with `INVENTORY_RECIPE_SHORTAGE` and a per-component list when any component is short, and refused when a component or the output is SERIAL-tracked or a LOT-tracked output has no `outputLotCode`. `UPDATE` replaces the fields and, when given, the whole line set; `ARCHIVE` keeps the row; both compare-and-swap on `version`; manager authority, FR-072 refusals, one audit row per write. A bundle (FR-154) is the special case "a kit at batch size 1"; offers and price tiers stay in Commerce. | 🟠 implemented locally 2026-09-06 — two models (both schemas, additive migration `20260906233000_inventory_recipe`; production SQL **not applied**), the only writer `inventory-recipe-service.js`, `GET/POST /api/inventory/recipes`, `GET/PATCH /api/inventory/recipes/[id]`, `POST /api/inventory/recipes/[id]/build`, snapshot coverage; one integration suite (AC-156.1–.5), calculators in the unit suite.
