| FR-155 | Inventory stock ledger — for a TRACKED product (FR-154), an append-only `StockMovement` (RECEIPT adds, ISSUE removes, ADJUSTMENT carries its own sign, with `reason`, `reference`, `actorId`, `occurredAt`); on-hand is the sum of a product's rows recomputed on every read and never stored on the product, a summary flags on-hand below `safetyStock`, and an UNTRACKED product is refused by code (`INVENTORY_PRODUCT_UNTRACKED`) and reports `null` on-hand, never zero. `ProductLot` (`lot_id`: `code` unique per product, optional factory, manufacture and expiry dates, `receivedQty`, OPEN / QUARANTINE / CLOSED) — a LOT-tracked receipt names a lot by id or creates it by code and the lot's `receivedQty` follows; a receipt into a CLOSED lot is refused. `SerialUnit` (`serial_id`: `serialNo` unique per product, IN_STOCK / RESERVED / ISSUED / RETURNED / SCRAPPED) — a SERIAL-tracked movement names exactly one serial per unit and writes one ledger row per unit; a unit is created IN_STOCK by its receipt, ISSUED by its issue, refused when received while IN_STOCK or issued while not, and ADJUSTMENT is not allowed on a serial product. A plain (NONE) product refuses a lot or a serial on the movement; an ISSUE that would take on-hand below zero is refused. Serial units are created only through the ledger (`GET`-only route); an explicit lot route exists for a dated batch before stock arrives. An ISSUE of a LOT-tracked SKU that names no lot is consumed **FEFO** — first expired, first out — across OPEN lots (unknown expiry last, whatever no lot holds last), one ledger row per lot touched and the allocation in the audit payload; an ISSUE that names a lot may not exceed that lot's on-hand (`INVENTORY_LOT_INSUFFICIENT_STOCK`); a lot listing reports each lot's on-hand from the ledger. Manager authority, FR-072 refusals, one transaction and one audit row per write with `onHandBefore` / `onHandAfter` in the payload. | 🟠 implemented locally 2026-09-06 — three models (both schemas, migrations shared with FR-154; production SQL **not applied**), the only writer `inventory-stock-service.js`, `GET/POST /api/inventory/lots`, `GET /api/inventory/serial-units`, `GET/POST /api/inventory/stock-movements`, `GET /api/inventory/stock`, the dashboard's KPIs, on-hand table and movement form; one integration suite (AC-155.1–.5), calculators in the unit suite. Not claimed: warehouse locations, reservations, expiry alerts, stocktake campaigns, costing |
