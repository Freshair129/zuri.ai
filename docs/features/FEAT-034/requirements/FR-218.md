| FR-218 | Programme usage report endpoint: `POST /api/platform/programme-usage-reports` lets an agent without local logs report one session's usage for one programme task — source, session id, task id, model, input, cache write, cache read and output tokens, request count, start and end time and active minutes — authenticated by the deployment bearer `ZURI_PROGRAMME_USAGE_TOKEN` (at least 32 characters, compared in constant time). A report is stored once per `(source, sessionId)` in `ProgrammeUsageReport`: the same payload again is an idempotent replay, a different payload for the same key is refused with 409, an unknown task id and an invalid body are refused by name, and a missing or wrong bearer answers 401 without reading the body. `/control/roadmap` reads the reports on the server and merges them with the meter's figures, skipping any report whose `source:sessionId` the meter already counted, and still renders when the table is absent. The Supabase migration ships with it; applying it on production is a separate operator step (ADR-057; ADR-086 D5). | ✅ deployed (ADR-086 D5) — `api/platform/programme-usage-reports`, `modules/platform-control/application/programme-usage-reports.js`; `tests/unit/programme-usage-reports.test.js`; merged #383 (6630c1df) and deployed as `zuri-ai-web:release-6630c1df`; migration `20260913230000_programme_usage_report` APPLIED on production 2026-09-14 (owner-instructed, ADR-057): read-only inventory, a rolled-back dry run through the transaction pooler, then apply with ledger row `20260913230000 programme_usage_report`; effect verified (15 columns, forced RLS, one `zuri_app_runtime_all` policy, grants to the two runtime roles only, unique (source, sessionId) and taskCode indexes, 0 rows); `ZURI_PROGRAMME_USAGE_TOKEN` not yet set, so every report is refused until the operator sets it |
