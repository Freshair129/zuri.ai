| FR-235 | LINE answer grounding from the published knowledge corpus: a LINE OA account carries a publisher-set `knowledgeGrounding` mode — `BUSINESS_KNOWLEDGE` (default, today's behaviour), `GKS_CORPUS` or `GKS_THEN_BUSINESS_KNOWLEDGE`. In a corpus mode a server-owned LINE job's answer reads the Business's published corpus generation through an in-process reader that implements the existing `knowledge.query` port over `queryKnowledgeCorpus` under the scoped runtime knowledge capability, within a configurable budget (2 500 ms, five results, an evidence packet of at most 8 KiB). A timeout or error is `GKS_UNAVAILABLE` and an empty result `NO_EVIDENCE`; either falls back to business knowledge only in `GKS_THEN_BUSINESS_KNOWLEDGE`, and every hop is traced as `EVIDENCE_SELECTED` with its source, reason, budget and retrieval references (citation, source, snapshot and corpus generation). No evidence from any allowed source means the deterministic reply and no model call. The first Business switched is SmartGift, after ADR-075 Phase 3 is deployed. A separate default-off GENESISRAG17_CUSTOMER_PRODUCTS descriptive path reads only enabled owner-approved per-Product/per-field policies for the current LINE OA account and constrains retrieval to their source IDs before querying. It resolves one Product from an exact approved public SKU or unique approved name, then verifies current owner authority, manifest/receipt/PCAT lineage, the exact ProductMaster record-to-live-Product binding and projection hash. Its packet contains only selected values and opaque fact IDs; model output is strict JSON factIds, unknown/duplicate/extra values and prose are rejected, and a fixed Thai renderer emits exact approved facts. Missing approval, ambiguity or stale proof prevents inference. Invalid model selection yields the deterministic no-evidence reply; neither case allows fixture, broad-corpus or business-knowledge fallback. It does not use memory, grant stock/price access or widen FR-291; owner policy, source and Product are revalidated before and after generation and at the durable SENDING authorization claim. Policy changes serialize with that claim and return a retryable conflict without mutation while an attempt is SENDING; after settlement/recovery withdrawal remains possible even when the source is unavailable. An already claimed network attempt cannot be recalled. Existing GKS_CORPUS and GKS_THEN_BUSINESS_KNOWLEDGE behavior is unchanged. | ✅ merged #407 2026-09-14 (main af3f7822; not deployed; TASK-ZAI-093, ADR-090 D1–D5, FEAT-038) — `LineOaAccount.knowledgeGrounding`, the in-process `knowledge.query` reader and the traced mode-gated fallback; the SmartGift switch itself is TASK-ZAI-095, blocked on ADR-075 Phase 3; the separate customer-product path is implemented, default OFF; main-dev activation and live customer-product RAG/LINE acceptance remain pending |
