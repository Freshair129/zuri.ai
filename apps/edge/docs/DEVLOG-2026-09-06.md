# Devlog — 2026-09-06

A record of one day, kept because the interesting part is not what shipped but what kept turning up
underneath it. Nine commits here, plus a release of the shared `rwang` plugin and a vendor bump in
`rwang-personal-assistant`.

## The thread

Everything on this list came out of one question — *are the requirement ids in this repository
actually traced?* — and every step of following it turned up a tool that was reporting less than the
truth without saying so.

| | before | after |
|---|---|---|
| Registered requirements | 92 (25 of them ids that do not exist) | 142 |
| Requirements with an `implements` edge | 34 | 72 |
| Requirements with a `verified_by` edge | 20 | 72 |
| Requirements with code and no test | — | **0** |
| Tests run by `npm test` | 837 | 896 |
| Graph edges | 184 | 347 |

## 1. A namespaced id is one id

The bootstrap scanner matched requirement ids with a word boundary on the left. A boundary sits
happily between the `-` and the `F` of a namespaced id, so the scan took the tail of `ZPP-FR-009`
for a PRD-SDD requirement of the same number. The two numbering schemes overlap across their whole
range, so this was not a near miss: **25 registry entities named ids that exist nowhere**, and 27
more claimed a plugin, RAG or taxonomy spec discussed a PRD-SDD requirement it had never mentioned.

Three local namespaces were being erased this way — `ZPP-*`, `RAG-*`, `TAX-*`. Appendix D §D.10 had
proposed exactly this prefix convention as the fix for cross-repository id collisions, without
noticing the repository was already using it and the tooling was not.

The rule is one line: a match may not begin in the middle of an identifier.

## 2. The same defect in the shared tooling

`rwang-plugin`'s two scanners had it too, and **failed in opposite directions**: the shell one
reported the bare tail as though it were a PRD-SDD requirement, the PowerShell one reported nothing
at all. Four more silent losses turned up while verifying the fix:

- The PowerShell skip list matched substrings of the whole path, so `build` swallowed `builder.ts`.
- One unrecognised id in a list discarded the recognised ones with it.
- A UTF-8 BOM hid line 1 from the shell scanner — which is where a file-level annotation goes.
- An annotation-free tree crashed the shell scanner instead of returning an empty report.

Released as `rwang` v1.4.0, which also learned `@tested <requirement-id>` on a test file. Until then
this repository's `tests/` tree read as **zero annotations while holding sixty-nine** — a silence,
not a warning.

The vendored copy in `rwang-personal-assistant` was synced. Two things surfaced there: earlier
vendored copies stripped the UTF-8 BOM from every `.ps1`, and PowerShell 5.1 reads a BOM-less script
in the system codepage, so the vendored scanner had been dropping every `@designs §…` annotation
silently — the same scanner finds 2 annotations with the BOM and 1 without.

## 3. The graph is now checked by something that did not write it

The graph was projected by a scanner written for this repository, and the defect above was found in
that same scanner — for a while the thing being checked and the thing doing the checking had one
author. Running the official `rwang` scanner against this tree now reproduces the edge set exactly:
81 `implements` and 75 `verified_by`, the same set of `(file, requirement id)` pairs, from two
implementations in different languages walking the tree by different means.

## 4. BR-010 — the archive holds both halves of a conversation

The LINE archive held every inbound message and none of the outbound ones: enough to show what a
customer asked and not what they were answered. A live test made it concrete — the question was
archived, the reply was delivered, and nothing on disk showed the reply had existed.

Now: group replies, the outbox worker's slow answers, and direct conversations under
`_dm/<16 hex of the keyed sender hash>/`, with the directory derived rather than stored so no raw
LINE id reaches the disk on either side. Retention runs on two clocks — 30 days for group history,
7 for a private conversation.

The invariant worth stating is not *the archive holds every outbound message* — it does not, and
says so — but **every place a message leaves offers it, and the archive decides whether it has
somewhere honest to file it**. A send site the archive cannot see is how the outbound half went
unrecorded to begin with.

## 5. Nothing is excluded from testing any more

`RAG-OPS-001` — the readiness and single-owner guard on the GenesisBlock store — was the one
requirement with implementing code and no test, on grounds I had written into the code myself:
reaching it needs the native binding and a real store. That conflated two things. Deciding *not* to
open is a decision taken before anything is opened, so every refusal is testable with no engine at
all. The ingest does need one, and now has an integration suite that runs wherever the binding is
installed and is skipped by name where it is not.

The best evidence in the day came out of that suite by accident. A second `GenesisNativeCatalog`
pointed at a store someone already owns returns false from `init` and then refuses to serve, naming
`GENESIS_STORE_ALREADY_OPEN`. The single-owner half of the requirement had been a property of the
design that nothing demonstrated; it is now a property something checks. The owner being unaffected
by the refused attempt is asserted too, because a guard that breaks the holder while turning away
the intruder is not a guard.

## What this cost, and what it was worth

Three defects found in the archive work had nothing to do with the feature: retention did not reach
the new directory depth (private messages would have been kept forever, on exactly the content most
worth expiring); deciding a destination by configuration rather than by the id's shape would have
filed an unconfigured group under a conversation hash, as though a group were a person; and
`npm test` is an explicit file list rather than a glob, so two suites added that morning had never
run while their annotations were putting edges in the graph.

That last one is the day in miniature. A test file that does not run is worse than no test file,
because the graph believes it.

## Corrections to my own claims, kept rather than tidied away

- I said `zuri-ai` has no encryption at rest. It has a Supabase Vault.
- I described the outbox worker as leaving a gap in the group archive. It cannot: the queue only
  ever holds direct messages, because the webhook enqueues under `source.type === 'user'`.
- I wrote in the code that `RAG-OPS-001` could not be tested without the native binding. That
  conflated the successful ingest, which does need an engine, with the refusals, which are decisions
  taken before anything is opened. It has six tests now.
- Explaining the truncation bug in §D.10, I wrote the truncated id in prose — and the scanner
  registered it as a requirement, correctly by its own rules. The passage now describes the
  truncation without spelling its result.

## Still open

Nothing in this repository is now excluded from testing on the grounds of needing an engine, and no
requirement has code without a test. What is left is elsewhere or environmental:

- `rwang-personal-assistant`'s CI runs only on `main` pushes and PRs into `main`, so a branch push
  is unchecked. The vendor bump was merged through a PR for exactly that reason.
- The DuckDB query slice still skips four cases without `SMARTGIFT_DUCKDB_PATH`, and the
  GenesisBlock ingest suite skips where the native binding is absent. Both say so by name rather
  than passing quietly, which is the most an environment-gated test can honestly do.
- `feat/tauri-desktop` was deleted after its work landed on `main` by squash merge; the tip was
  `59ef55c` should anyone need to restore it.

## Closing the day

Two things worth carrying forward. The first is that every defect on this list was silent — not one
of them produced an error, a warning, or a failing test. They produced smaller numbers, stated
confidently. A tool that reports less than the truth without saying so is worse than one that
breaks, because nothing prompts you to look.

The second is that the graph is now checked by something that did not write it, and the last
requirement anyone had written off as untestable turned out to be testable by someone willing to
ask which half was actually hard. Both of those are cheaper to keep than they were to establish.
